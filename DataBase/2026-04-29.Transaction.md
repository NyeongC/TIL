## 트랜잭션이란?

### 개념
```
트랜잭션은 데이터베이스에서 하나의 논리적인 작업 단위로, 모든 작업이 성공하면 커밋되고 하나라도 실패하면 전체가 롤백되어 데이터의 일관성을 보장하는 개념이다.
```
---

### 예시

A → B 10만원 계좌 이체

* A는 -10만원
* B는 +10만원

> 이 두 작업은 반드시 같이 성공해야 함   
> 하나라도 실패하면 전체 취소 (Rollback)   
--- 
### 특징 (ACID)
* Atomicity (원자성)
→ 전부 성공하거나 전부 실패
* Consistency (일관성)
→ 트랜잭션 전후 데이터 상태가 항상 일관됨
* Isolation (격리성)
→ 동시에 실행되는 트랜잭션 간 간섭 없음
* Durability (지속성)
→ 커밋된 데이터는 영구적으로 반영됨
---

### 스프링 @Transactional 원리
> 스프링은 AOP(프록시)를 사용해 트랜잭션을 관리한다.

1. 메소드 호출 시 프록시 객체가 먼저 실행됨
2. 트랜잭션 시작 (begin)
3. 실제 메소드 실행
4. 정상 종료 → commit
5. 예외 발생 → rollback
---
> 핵심

* 실제 메소드 앞뒤로 트랜잭션 로직이 감싸짐
* try-catch로 직접 쓰는 게 아니라 프록시가 대신 처리

```
트랜잭션 구조

[프록시]
   ↓
트랜잭션 시작
   ↓
[비즈니스 로직 실행]
   ↓
정상 → commit
예외 → rollback
```

**스프링은 프록시(AOP)를 이용해 메소드 실행 전에 트랜잭션을 시작하고, 정상 종료 시 커밋하며, RuntimeException 발생 시 롤백한다.**
