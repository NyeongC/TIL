## 동시성 제어 전략 (낙관적 락 vs 비관적 락)

### DB Lock 이란?

> DB에서 여러 트랜잭션이 동시에 같은 데이터를 접근할 때 발생하는 충돌을 방지하기 위해, 데이터 접근을 제어하는 메커니즘

### 낙관적 락 (Optimistic Lock)
#### 개념

> 조회는 자유롭게 하고, 수정 시점에 버전 값(version)을 비교하여 충돌 여부를 판단   
→ 충돌 시 실패 처리

#### 특징
* DB 락을 걸지 않음
* 수정 시점에만 충돌 체크
* 보통 version 컬럼 사용 (JPA @Version)
#### 장점
* 성능 좋음 (락 없음 → 대기 없음)
* 트래픽 많은 환경에 유리
* DB 부하 적음
#### 단점
* 충돌 시 실패 → 재시도 로직 필요
* 충돌이 잦으면 오히려 비효율
* 사용자 경험 저하 가능
#### 언제 사용하나
* 충돌 가능성이 낮은 경우
* 조회가 많고 수정이 적은 서비스
* 성능이 중요한 시스템
#### 예시
* 게시판 조회/수정
* 사용자 프로필 수정
* 일반 CRUD 서비스
--- 
### 비관적 락 (Pessimistic Lock)
#### 개념

> 수정이 예상되면 미리 DB 락을 걸어서 다른 트랜잭션 접근 차단

#### 특징
* 트랜잭션 시작 시점에 락 획득
* 다른 트랜잭션은 대기 또는 실패
* SELECT ... FOR UPDATE 방식
#### 장점
* 데이터 정합성 강력하게 보장
* 충돌 자체를 방지
* 재시도 로직 불필요
#### 단점
* 성능 저하 (락 대기 발생)
* 데드락 가능성 존재
* 트래픽 많으면 병목 발생
#### 언제 사용하나
* 데이터 정합성이 매우 중요한 경우
* 동시에 수정될 가능성이 높은 경우
* 실패 자체가 치명적인 경우
#### 예시
* 재고 차감 (쇼핑몰 주문)
* 계좌 이체 / 금융 거래
* 좌석 예약 시스템
---
### 한 줄 정리
* 낙관적 락 → "일단 처리하고, 충돌 나면 실패" (성능 중심)
* 비관적 락 → "애초에 충돌 못하게 막는다" (정합성 중심)
