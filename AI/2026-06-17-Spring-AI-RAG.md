# RAG

## 1. RAG가 필요한 이유

LLM은 기본적으로 학습된 데이터 기반으로 답변한다.

따라서 학습 이후의 정보나 회사 내부 문서 같은 정보는 알 수 없다.

예)

``` text
최신 공지
회사 내부 규정
최근 정책
개인 프로젝트 문서
```

이런 정보는 LLM이 원래 알고 있는 지식이 아니기 때문에

``` text
모르거나
그럴듯하게 지어낼 수 있다.
```

이런 문제를 줄이기 위해 사용하는 방식이 RAG이다.

------------------------------------------------------------------------

## 2. RAG란?

RAG는

``` text
Retrieval Augmented Generation
```

의 약자이다.

의미는

``` text
검색(Retrieval)으로 가져온 정보를 바탕으로
답변(Generation)을 생성하는 방식
```

이다.

즉,

``` text
관련 정보 조회
↓
프롬프트 추가
↓
LLM 질의
```

구조이다.

------------------------------------------------------------------------

## 3. RAG 동작 흐름

Spring AI에서 가장 흔한 형태

``` text
사용자 질문
↓
질문 임베딩
↓
벡터 저장소 검색
↓
관련 문서 조회
↓
프롬프트 증강
↓
LLM
↓
답변
```

※ RAG 자체가 반드시 벡터 저장소만 사용하는 것은 아니다. DB, API,
검색엔진도 Retrieval 대상이 될 수 있다. 다만 Spring AI에서는 보통
VectorStore 기반 RAG를 사용한다.

------------------------------------------------------------------------

## 4. RAG와 일반 LLM 질의 차이

일반 LLM

``` text
사용자 질문
↓
LLM
↓
답변
```

RAG

``` text
사용자 질문
↓
정보 조회
↓
프롬프트 증강
↓
LLM
↓
답변
```

차이점은

``` text
추가 지식을 검색해서 참고하느냐
```

이다.

반드시 외부 문서일 필요는 없다.

``` text
사내 위키
Notion
PDF
DB 데이터
API 결과
벡터 저장소
```

모두 가능하다.

------------------------------------------------------------------------

## 8. Chunk란?

Chunk는 문서를 일정 크기로 나눈 조각이다.

예)

사용자 매뉴얼

``` text
1장 회원가입
2장 로그인
3장 비밀번호 찾기
4장 게시글 작성
5장 결제
```

Chunk 분할

``` text
Chunk1 = 회원가입

Chunk2 = 로그인

Chunk3 = 비밀번호 찾기

Chunk4 = 게시글 작성

Chunk5 = 결제
```

사용자가

``` text
비밀번호 찾기 방법 알려줘
```

라고 질문하면

``` text
Chunk3
```

를 찾아서 LLM에 전달한다.

전체 문서를 넣는 것이 아니라 관련 있는 조각만 넣는다.

------------------------------------------------------------------------

## 13. 핵심 정리

``` text
RAG
= 검색된 정보를 프롬프트에 추가하여 답변 생성

LLM 단독 질의
= 학습된 지식만 사용

RAG
= 추가 지식을 검색하여 활용

ETL
= 문서를 읽고 가공하고 저장하는 과정

VectorStore
= 임베딩 벡터 저장소

Chunk
= 문서를 나눈 조각

QuestionAnswerAdvisor
= 기본 RAG Advisor

RetrievalAugmentationAdvisor
= 확장형 RAG Advisor
```
