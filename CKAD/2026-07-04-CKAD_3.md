## Pod Security Context

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: secure-app-pod
  namespace: security
spec:
  # Pod 안의 모든 컨테이너에 기본 적용
  securityContext:
    runAsUser: 1000
    runAsGroup: 3000
    runAsNonRoot: true

  containers:
  - name: app-container
    image: busybox:1.36
    command: ["sleep", "3600"]

    # 해당 컨테이너에만 적용
    securityContext:
      readOnlyRootFilesystem: true
```

### 주요 설정값

* `runAsUser: 1000`: 프로세스를 UID 1000 사용자로 실행
* `runAsGroup: 3000`: 프로세스의 기본 그룹을 GID 3000으로 설정
* `runAsNonRoot: true`: root 사용자로 실행되는 것을 차단
* `readOnlyRootFilesystem: true`: 컨테이너의 루트 파일시스템을 읽기 전용으로 설정

`spec.securityContext`는 Pod 전체 기본 설정이고,
`containers[].securityContext`는 특정 컨테이너에만 적용된다.

## Job YAML 파일 생성

```bash
cat <<EOF > /opt/course/3/job.yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: neb-new-job
  namespace: neptune
spec:
  parallelism: 2
  completions: 3

  template:
    metadata:
      labels:
        id: awesome-job
    spec:
      containers:
      - name: neb-new-job-container
        image: public.ecr.aws/docker/library/busybox:stable
        command: ["sh", "-c", "sleep 2 && echo done"]

      restartPolicy: Never
EOF
```

```bash
kubectl apply -f /opt/course/3/job.yaml
```

### 주요 설정값

* `completions: 3`: 총 3개의 Pod가 성공해야 Job 완료
* `parallelism: 2`: 동시에 최대 2개까지 실행
* `restartPolicy: Never`: 종료된 컨테이너를 같은 Pod에서 재시작하지 않음

### Pod 라벨 위치

Job이 생성하는 Pod의 라벨은 다음 위치에 작성한다.

```yaml
spec:
  template:
    metadata:
      labels:
        id: awesome-job
```

Job 자체의 `metadata.labels`에 넣으면 Job에만 라벨이 붙는다.

### command 작성

```yaml
command: ["sh", "-c", "sleep 2 && echo done"]
```

`&&`, 파이프, 리다이렉션처럼 쉘 문법이 들어가면 `sh -c`가 필요하다.

### cat 명령어

```bash
cat <<EOF > 파일경로
내용
EOF
```

* `>`: 파일을 새로 만들거나 기존 내용을 덮어씀
* `EOF` 사이의 내용을 지정한 파일에 저장
* 파일 생성만 하므로 이후 `kubectl apply -f 파일경로`가 필요

## PV, PVC, Deployment 연결

### 개념

* **PV**: 클러스터에 준비된 실제 저장 공간
* **PVC**: Pod가 필요한 저장 공간을 요청하는 객체
* **Deployment/Pod**: PVC를 연결하여 컨테이너 내부 경로에 마운트

일반적인 생성 순서:

```text
PV → PVC → Deployment
```

### 1. PersistentVolume 생성

```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: earth-project-earthflower-pv
spec:
  capacity:
    storage: 2Gi
  accessModes:
    - ReadWriteOnce
  hostPath:
    path: "/Volumes/Data"
  storageClassName: ""
```

* `capacity.storage`: PV가 제공하는 저장 공간
* `accessModes`: 볼륨 접근 방식
* `hostPath.path`: 노드에 실제 데이터가 저장되는 경로
* PV는 Namespace에 속하지 않는 클러스터 리소스

### 2. PersistentVolumeClaim 생성

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: earth-project-earthflower-pvc
  namespace: earth
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 2Gi
  storageClassName: ""
```

PVC가 PV에 연결되려면 다음 조건이 맞아야 한다.

* `storageClassName`
* `accessModes`
* PVC 요청 용량이 PV 용량 이하일 것

PV 이름과 PVC 이름은 같을 필요가 없다.

```bash
kubectl get pv
kubectl -n earth get pvc
```

PVC 상태가 `Bound`이면 정상 연결된 것이다.

### 3. Deployment에서 PVC 사용

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: project-earthflower
  namespace: earth
spec:
  replicas: 1
  selector:
    matchLabels:
      app: project-earthflower
  template:
    metadata:
      labels:
        app: project-earthflower
    spec:
      containers:
      - name: web
        image: httpd:2.4.41-alpine
        volumeMounts:
        - name: storage
          mountPath: /tmp/project-data

      volumes:
      - name: storage
        persistentVolumeClaim:
          claimName: earth-project-earthflower-pvc
```

### 반드시 같아야 하는 값

Deployment의 Selector와 Pod 라벨:

```yaml
selector:
  matchLabels:
    app: project-earthflower

template:
  metadata:
    labels:
      app: project-earthflower
```

컨테이너의 VolumeMount 이름과 Pod의 Volume 이름:

```yaml
volumeMounts:
- name: storage

volumes:
- name: storage
```

PVC 이름과 `claimName`:

```yaml
metadata:
  name: earth-project-earthflower-pvc
```

```yaml
claimName: earth-project-earthflower-pvc
```

### 경로 구분

```yaml
hostPath:
  path: /Volumes/Data
```

노드의 실제 저장 경로이다.

```yaml
mountPath: /tmp/project-data
```

컨테이너 내부에서 볼륨이 보이는 경로이다.
