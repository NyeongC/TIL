## 포트 포워딩 등 서버 아키텍쳐

### 포트 포워딩

* 외부에서 들어온 특정 포트 요청을 내부의 다른 IP/포트로 전달하는 것
* 공인IP로 들어온 요청을 사설망 서버로 연결
주로 NAT / 방화벽 / 공유기 / 클라우드 네트워크 레벨에서 처리
* 내부 서버를 직접 노출하지 않고 접근 가능하게 함

#### 예시
공인IP:80 → 10.0.0.5:8080   

외부 사용자 → 공인IP:80 → 포트 포워딩 → 사설IP:8080 → Spring Boot   

--- 

### 리버스 프록시 (Reverse Proxy)

* 클라이언트 대신 요청을 받아서 내부 서버로 전달하고, 결과를 다시 클라이언트에게 반환하는 서버
* 클라이언트는 실제 서버(Spring)를 모름
* 항상 프록시(Nginx)만 바라봄
* 내부 구조 숨김 (보안)
* SSL 처리, 인증, 로깅 등 중앙 처리 가능

#### 흐름

사용자 → Nginx → Spring → Nginx → 사용자

#### 예시 (Nginx)
```
location / {
    proxy_pass http://10.0.0.5:8080;
}
```
---
### 로드 밸런싱

* 여러 서버에 트래픽을 분산시켜 부하를 나누는 것
* 서버 1대에 몰리는 트래픽 분산
* 장애 발생 시 다른 서버로 처리 가능 (가용성 증가)
* 수평 확장 구조의 핵심

#### 예시
```
upstream backend {
    server 10.0.0.5:8080;
    server 10.0.0.6:8080;
}
```
---
### 리버스 프록시 vs 포트포워딩 (진짜 중요한 차이)

> 둘 다 “전달”이지만 레벨이 다름

포트포워딩 → 네트워크 레벨 (단순 전달)
리버스프록시 → 애플리케이션 레벨 (HTTP 이해하고 처리)


---

### 전체 아키텍처

사용자 → 공인IP (Nginx) → 내부 서버 분산

Server2 (Spring), Server3 (Spring)

→ DB 서버
```bash
[사용자]
    ↓
http://공인IP (Server1 - Nginx)
    ↓
(포트포워딩 + 리버스프록시)
    ↓
-----------------------------
↓                           ↓
Server2 (10.0.0.5:8080)   Server3 (10.0.0.6:8080)
(Spring Boot)              (Spring Boot)
-----------------------------
        ↓
   Server4 (DB)
```

---

### 요청 흐름
```
1. 사용자가 공인 IP로 요청
2. Nginx가 요청 수신
3. Nginx가 내부 서버로 분산
4. Spring Boot가 비즈니스 처리
5. DB 조회/저장
6. 응답 반환
```

---

### Nginx 설정

``` nginx
upstream backend {
    server 10.0.0.5:8080;
    server 10.0.0.6:8080;
}

server {
    listen 80;

    location / {
        proxy_pass http://backend;
    }
}
```

---

### HTTP → HTTPS 리다이렉트

> 보통 Nginx에서 처리

``` nginx
server {
    listen 80;
    server_name example.com;

    return 301 https://$host$request_uri;
}
```

✔ HTTP 요청을 HTTPS로 강제 변경\
✔ SSL은 443 포트에서 처리

### 한방 정리

“포트 포워딩은 네트워크 레벨에서 요청을 내부 서버로 전달하는 기술이고, 리버스 프록시는 클라이언트 대신 요청을 받아 내부 서버로 전달하면서 보안, 로깅, SSL 처리 등을 수행하는 애플리케이션 레벨의 프록시입니다. 로드 밸런싱은 이러한 구조에서 여러 서버로 트래픽을 분산하는 역할을 합니다.”
