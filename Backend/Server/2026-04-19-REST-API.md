# REST API 정리

### 1. API(Application Programming Interface)란?

*   **정의**: 프로그램과 프로그램이 서로 데이터를 주고받기 위한 **규약(명세)**입니다.
*   **역할**: 네트워크 환경에서 클라이언트의 요청을 서버에 전달하고, 그 결과를 다시 클라이언트에게 돌려주는 **매개체** 역할을 합니다.
*   **비유**: 레스토랑에서 손님(클라이언트)의 주문을 주방(서버)에 전달하는 **점원**과 같습니다.

---

### 2. REST API란?

*   **REpresentational State Transfer**: "자원의 상태를 주고받는 것"을 의미하는 아키텍처 스타일입니다.
*   **핵심 개념**: 자원(Resource)은 **URI**로 표현하고, 행위(Verb)는 **HTTP Method**를 통해 표현합니다.
*   **특징**: 특정 기술이나 프로토콜이 아닌 하나의 **설계 원칙**입니다.
*   **한 줄 요약**: 누구나 URI만 보고도 "이 API가 무엇을 하는지" 직관적으로 이해할 수 있는 API입니다.

---

### 3. 장단점

#### ✅ 장점
*   **직관성**: URI와 HTTP Method만 보고도 어떤 기능을 수행하는지 알 수 있습니다.
*   **무상태성(Stateless)**: 서버가 클라이언트의 상태를 보관하지 않아 자유로운 확장성을 가집니다.
*   **독립성**: HTTP 표준만 따르면 플랫폼(Java, Python, Vue 등)에 상관없이 사용 가능합니다.
*   **경량성**: 주로 JSON 형식을 사용하여 데이터 전송량이 적고 가볍습니다.

#### ❌ 단점
*   **표준의 부재**: 공식적인 표준이 없어 팀마다 구현 방식이 조금씩 다를 수 있습니다. (설계 가이드만 존재)
*   **제한적인 Method**: HTTP Method(GET, POST 등)만으로는 복잡한 로직을 표현하기 어려울 때가 있습니다.

---

### 4. REST API 설계 규칙 (핵심)

가장 중요한 것은 **"자원은 명사로, 행위는 메서드로"** 표현하는 것입니다.

#### 📌 URI 설계 5대 규칙
1.  **동사보다는 명사를 사용한다.**
    *   (Bad) `/getArticle/1`, `/deleteUser`
    *   (Good) `/articles/1`, `/users`
2.  **소문자를 사용한다.**
    *   (Bad) `/UserPosts`
    *   (Good) `/user-posts`
3.  **언더바(`_`) 대신 하이픈(`-`)을 사용한다.** (가독성 목적)
4.  **마지막에 슬래시(`/`)를 포함하지 않는다.**
    *   (Bad) `/articles/`
    *   (Good) `/articles`
5.  **파일 확장자는 URI에 포함하지 않는다.**
    *   (Bad) `/image.jpg` (대신 Accept 헤더를 활용)

---

### 5. HTTP Method와 자원의 관계 (CRUD)

| 행위(Verb) | 의미 | 비고 |
| :--- | :--- | :--- |
| **GET** | 조회 (Read) | 자원의 정보를 가져옴 |
| **POST** | 생성 (Create) | 새로운 자원을 생성함 |
| **PUT** | 수정 (Update) | 자원의 전체를 교체함 |
| **PATCH** | 수정 (Update) | 자원의 일부만 수정함 |
| **DELETE** | 삭제 (Delete) | 자원을 제거함 |

---

### 6. 사용 방식 및 예시

#### ❌ REST API가 아닌 방식 (RPC 스타일)
```text
GET: /getArticle?id=1    (동사 'get' 사용, 쿼리 파라미터로 식별)
POST: /update_article    (동사 'update' 사용)
```

#### ✅ REST API 표준 방식
```text
GET: /articles/1         (명사 'articles'와 경로 변수 사용)
POST: /articles          (새로운 게시글 생성)
DELETE: /articles/1      (1번 게시글 삭제)
```

> **Tip**: REST API는 단순한 URL 주소가 아니라, **"어떤 자원(/articles/1)을 어떻게(GET, DELETE)"** 다룰 것인가에 대한 약속입니다.
