## DI의 방식 중 생성자 주입이 좋은 이유

생성자 주입은 객체 생성 시점에 의존성을 반드시 주입받도록 강제한다.  
따라서 의존성 누락을 컴파일 시점에 방지할 수 있다.

또한 final과 함께 사용하면 의존성이 변경되지 않아 객체의 안정성을 보장한다.

👉 테스트 시 스프링 없이도 객체 생성이 가능하다
```java
UserController controller = new UserController(mockService);
```

---

## 필드 주입(@Autowired)을 잘 사용하지 않는 이유

필드 주입은 외부에서 의존성이 어떻게 주입되는지 명확하게 드러나지 않는다.  
또한 테스트 시 객체를 직접 생성하기 어렵고, 의존성 주입이 강제되지 않는다.

👉 테스트를 위해 스프링 컨테이너를 띄워야 한다 (무거움)
```java
@SpringBootTest
class Test {
    @Autowired 
    UserController controller;
}
```

---

## 세터 주입이 좋지 않은 이유

세터 주입은 객체 생성 이후에도 의존성을 변경할 수 있어  
객체의 상태가 변할 가능성이 있다.

또한 setter를 호출하지 않으면 필수 의존성이 주입되지 않은 상태로  
객체가 생성될 수 있다.

👉 언제든 의존성 변경 가능 (안정성 낮음)
```java
controller.setUserService(null);
```
