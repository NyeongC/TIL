## 스프링 빈(Bean)이란?

->
스프링 컨테이너가 생성하고 관리하는 객체

* 우리가 `new`로 직접 만든 객체 ❌
* 스프링이 대신 만들어주고 관리하는 객체 ⭕

---

## 빈 등록 방법

### 1. 컴포넌트 스캔

```java
@Service
@Repository
@Controller
```

-> 어노테이션 붙이면 자동 등록

---

### 2. 직접 등록

```java
@Bean
public UserService userService() {
    return new UserService();
}
```

-> 설정 클래스에서 수동 등록

---

## 싱글톤(Singleton)이란?

```
애플리케이션 내에서 단 하나의 객체만 생성하여 공유하는 패턴
```
->
스프링은 기본적으로 **빈을 하나만 생성해서 공유함**

```java
UserService a = context.getBean(UserService.class);
UserService b = context.getBean(UserService.class);
```

-> a == b (같은 객체)

---

## 왜 싱글톤이 중요한가?

### 1. 메모리 절약

* 객체를 계속 생성하지 않음
* 서버 자원 효율적

---

### 2. 성능 향상

* 매번 new 안함
* 빠른 응답

---

### 3. 일관성 유지

* 하나의 객체를 여러 곳에서 공유

---

## 실무에서 진짜 중요한 포인트

-> 싱글톤은 **무조건 무상태(stateless)** 로 설계해야 함

```java
// ❌ 위험한 코드
private int count;
```

-> 여러 요청이 동시에 접근하면
-> 데이터 꼬임 (동시성 문제 발생)

---

## ✅ 안전한 설계

```java
public int calculate(int a, int b) {
    return a + b;
}
```

-> 상태 저장 ❌
-> 요청마다 독립적으로 처리 ⭕

---

## 한 줄 핵심

->
스프링 빈은 컨테이너가 관리하는 객체이고,
기본적으로 싱글톤으로 생성되어 공유되기 때문에 무상태로 설계해야 한다.

---

## 실무 연결

* Controller / Service / Repository 전부 싱글톤
* 트래픽 많을수록 더 중요
* 상태 넣으면 바로 장애로 이어짐
