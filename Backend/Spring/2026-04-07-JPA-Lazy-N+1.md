# 📌 Spring JPA 프록시 & 지연 로딩 정리

---

## 📖 한줄 요약

- 프록시 → 지연 로딩을 위해 사용
- 지연 로딩 → 필요할 때 DB 조회
- 문제 → N+1 발생
- 해결 → fetch join

---

## 📌 1. JPA에서 프록시를 쓰는 이유

👉  
지연 로딩을 구현하기 위해 사용

👉  
실제 객체 대신 프록시 객체를 넣어두고,  
필요할 때 실제 조회 수행

---

## 📌 2. 지연 로딩 (Lazy Loading)

👉  
연관 데이터를 미리 조회하지 않고, 사용할 때 조회하는 방식

---

### 🔹 예시

```java
Order order = orderRepository.findById(1L).get();

// 아직 member 조회 안됨 (프록시)
Member member = order.getMember();

// 여기서 DB 조회 발생
member.getName();
```

---

## 📌 장점

- 불필요한 조회 방지
- 성능 최적화
- 필요한 데이터만 조회

---

## 📌 3. 문제점 (N+1 문제)

👉  
연관 데이터를 조회할 때 쿼리가 반복 발생

---

### 🔹 예시

```java
List<Order> orders = orderRepository.findAll();

for (Order order : orders) {
    order.getMember().getName(); // N번 조회 발생
}
```

---

### 🔹 실제 쿼리

```sql
SELECT * FROM orders; -- 1번

SELECT * FROM member WHERE id = 1;
SELECT * FROM member WHERE id = 2;
SELECT * FROM member WHERE id = 3;
```

👉 총 1 + N번 쿼리

---

## 📌 4. 해결 방법

### 🔹 fetch join

```java
@Query("select o from Order o join fetch o.member")
List<Order> findAllWithMember();
```

👉 한 번에 조회

---

### 🔹 결과 쿼리

```sql
SELECT *
FROM orders o
JOIN member m ON o.member_id = m.id;
```

---

## 📌 한줄 정리

👉  
지연 로딩은 프록시를 사용해 필요할 때 DB 조회하는 전략이며,  
N+1 문제가 발생할 수 있어 fetch join으로 해결한다
